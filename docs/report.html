Experiment 3: Batched Script vs Per-Call Tool Use

Method: Real token counting with tiktoken (cl100k_base / GPT-4o encoding) on 20 file operations. Real token counts

MetricPer-CallBatchedReduction
API requests20290%
Total tokens32,9811,81994.5%

Interpretation: Per-call re-sends growing context with every request (74 tokens at request 1 → 2,151 at request 20). Batching eliminates this quadratic growth. The 94.5% reduction aligns with the cited claim of ~98% for larger sessions.

Caveat: Measures token overhead, not correctness. Whether models produce reliable batch scripts is the open question.

Conclusions & Next Steps

High-Confidence (real measurements)

  1. Adopt batched tool calling. 94.5% token reduction is real. Even with a 10-20% retry rate, net positive.
  2. Enable prompt caching. 72% savings, break-even at turn 2. Requires only prompt structure changes.
  3. Add pane management to Rex. 1.83x speedup, trivial implementation (~80 lines).

Medium-Confidence (cost models)

  1. Two-tier model routing. 21% savings (conservative). Validate with A/B test on 50 real tasks.
  2. Writer/reviewer default pipeline. +15pp fix rate, -42% defect escapes. Calibrate with real LLM calls.

Longer-Term (design-stage)

  1. SuperPlane pattern for Landroval. State machine ready, 10-item capability checklist provided.
  2. herdr-core session persistence. Prototype works; wire into actual API.
