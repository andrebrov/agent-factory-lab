Research Findings

Six techniques for improving AI coding agents, each sourced from X with a proposal and experiment design.

1. Cross-Model Writer/Reviewer/QA Pipeline

Source: @brag_sheet on X

Idea

Use a multi-agent pipeline where distinct models fill separate roles — writer, reviewer, and QA — each operating in an isolated git worktree. A risk gate inspects the diff before auto-merging: low-risk changes merge automatically, high-risk changes pause for human review.

Proposal for Gwaihir

Make this pipeline Gwaihir's default execution mode. The writer spawns on a fresh worktree branch, a reviewer checks the diff (approve/request-changes/reject), a QA agent runs the test suite, and a deterministic risk gate (not LLM-based) scores the change by lines changed, files touched, and blast radius.

Experiment

Monte Carlo simulation: 1,000 trials per bug across 10 seeded bugs. Simulated — harness ready for real LLM calls.

2. Keep Frontier Models Off the Control Plane

Source: @adamhjk on X

Idea

Most orchestration work — status checks, routing, task decomposition — doesn't need frontier-level intelligence. Route the control plane to cheap/fast models (Claude Haiku, GPT-4o-mini) and reserve frontier models (Claude Opus, GPT-4) for actual code generation and complex reasoning.

Proposal for Gwaihir & Landroval

Two-tier architecture: cheap model handles task routing, status checks, file listing, grep/search. Frontier model handles code writing, complex debugging, architectural decisions. Estimated 60-70% of tokens go to orchestration, so moving them to a 10-20x cheaper model saves 50-65% of total cost.

Experiment

Cost model using public API pricing (Claude Opus vs Haiku) on a synthetic 17-step session. Estimated — real prices, synthetic trace.

3. Programmatic / Batched Tool Calling

Source: @MilanGlow on X

Idea

Instead of issuing tool calls one at a time, batch many operations into a single script. The cited result: ~312 individual tool calls / 3.1M tokens compressed to ~2 requests / 61K tokens.

Proposal for Gwaihir & Rex

When a task involves multiple file edits or shell commands, emit a single script instead of individual tool calls. The herdr runtime already supports shell execution; add a "batch mode" that encourages script emission.

Experiment

Real token counting with tiktoken on 20 file operations. Real token counts — 94.5% reduction measured.

4. Server-Side Prompt Caching

Sources: @ClaudeDevs, @tokenscost

Idea

Long coding sessions accumulate massive context windows. Without caching, every API call re-sends the full history at full price. Prompt caching stores and reuses the stable prefix (system prompt, tools, early context) at a steep discount (often 90% off).

Proposal for Gwaihir & Landroval

Structure prompts for cacheability: stable prefix at the top, append-only message history, never reorder mid-session. Enable Anthropic's cache_control breakpoints or OpenAI's automatic prefix caching.

Experiment

Token counting with tiktoken + Anthropic pricing over 20 simulated turns. Real token counts — 72.3% savings, break-even at turn 2.

5. Native Pane/Tab Control & Durable Session Layer

Sources: @dani_avila7, @herdrdev, @nicoritschel

Idea

Give the coding agent the ability to programmatically manage terminal panes (edit in one, test in another, monitor logs in a third). Pair with herdr-core's durable session layer for crash recovery and multi-agent state sharing.

Proposal for Rex & Gwaihir

Add a tmux pane-control skill to Rex. Use herdr-core's durable sessions to persist orchestrator state for crash recovery and agent hand-offs.

Experiment

Real tmux pane execution + JSON checkpoint/restore. Real execution — 1.83x speedup, zero state loss.

6. SuperPlane Backlog-to-Ship Pattern

Source: @darkofabijan on X

Idea

Automate the full lifecycle from backlog item to shipped code: issue triage, planning, execution, review, merge, deploy. The key insight is treating the entire pipeline as automatable, not just the code-writing step.

Proposal for Landroval

Landroval already covers code generation and test execution. Complete the SuperPlane pattern by adding backlog triage, approval gates, deploy triggers, and cycle-time metrics. A 10-item capability checklist is provided.

Experiment

State machine implementation with 5 sample issues. Simulated — design exercise with runnable code.
